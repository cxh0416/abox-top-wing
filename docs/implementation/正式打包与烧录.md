## 状态与配置边界

Full 内的 Boot、App 和独立文件逐字节一致；App 末尾至 State 起始之间填充 `0xFF`。State A 位于 `0x0803E800`，含匹配本次 App 长度、CRC 和版本的 V3 CONFIRMED 记录；State B 位于 `0x0803F000`，为擦除态，避免旧记录参与启动选择。

Full 截止于 `0x0803F7FF`，排除配置页 `0x0803F800..0x0803FFFF`。整包烧录须仅擦写文件覆盖的页并做读回校验；不整片擦除。独立调试器更新 App 时必须同时更新匹配 State。当前 `flash_full_jlink.ps1` 只适用于旧式不含 State 的 Full，正式包使用附带的烧录说明。

## 重建与检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build_release.ps1
python .\tools\verify_release.py .\dist --version top-flying-wing-1.1.8
python .\tests\test_release_package.py
```

产品软件回归使用 `build/host/`，ARM Release 构建复用 `build/app/`。正式打包沿用固定 Boot，不重新构建或修改 Boot。包校验覆盖文件集合、冻结 Boot、分区、向量、版本、App/State CRC、State B 擦除态、Full 组件一致性及双清单；破坏性样本仅在 `build/host/` 临时副本内构造。

本次 31 项软件回归、7 项实际烧录包测试及 ARM Release 构建通过。包测试包括有效包、App/State 错配、配置页越界、State B 残留、额外诊断文件、OTA 清单错配，以及暂存包校验失败时保留原正式目录；同时执行了对已有 `dist/` 的整体替换，替换前后 Full 哈希一致。校验摘要保存在本地 `build/app/release_verification_1.1.8.json`，不放入正式交付目录。

本次没有向开发板烧录或下发运动命令，构建和文件校验不作为真实运动或 OTA 成功证据。此前排查到的 9 条持久化去重容量限制，以及电阻式防夹条释放后残余导通问题，不属于本次打包流程修改的修复范围。
