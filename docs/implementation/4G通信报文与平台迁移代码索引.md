# 4G 通信报文与平台迁移代码索引（内部分析）

内部资料，不作为业务对接协议对外交付。依据当前工作区代码及正式包 `top-flying-wing-1.1.8` 整理；这是实现索引，公共接口合同仍以公共 MQTT V4 和飞翼业务 V4 协议为准。

以下示例仅说明结构，没有发送到设备；`timestamp` 和 `expiresAt` 示例值不能用于实际控制，实际请求须使用平台当前 UTC 毫秒时间。所有凭据均为占位值，不含设备密码。

## 1. 当前通信构成

设备通过 EC800 4G 模组接入网络，STM32 经 UART1 驱动 AT 指令。日常操控使用 MQTT JSON：公共业务为字符串版本 `4.0`，内部运维与授时为 `2.0`。HTTP/HTTPS 用于首次入网、凭据审批与固件下载，不是日常升降下控入口。

设备身份 `deviceId` 对应已保存的 VID，并用于 MQTT ClientId 和 Topic；产品标识始终为 `top_flying_wing`。业务报文不需要在 data 中额外加入 product 或 deviceType。当前 Profile 固定为单实例 `wing 1.0`，不发送 instanceId。

令 `B=/zxwl/abox/{deviceId}`，实际发送时替换 deviceId，不保留花括号。

## 2. 公共下控报文

### 2.1 上升、下降

发布到 `B/request`。`command=wing_control`；`params.action=ascend` 为上升，`descend` 为下降。新操作使用新的 requestId；同一次操作因网络重试，保留原 requestId 和原内容。

升降必须携带 data.expiresAt，满足 `0 < expiresAt - timestamp <= 5000 ms`。设备只有在可信时间足以确认请求仍有效时才执行。

```json
{
  "version": "4.0",
  "timestamp": 1793584800000,
  "data": {
    "requestId": "wing-up-001",
    "command": "wing_control",
    "params": {
      "action": "ascend"
    },
    "expiresAt": 1793584805000
  }
}
```

下降仅将 action 改为 `descend`，同时为新的操作生成新的 requestId 和时间字段。公共请求解析入口：[mqtt_v4.c:222](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:222)；动作声明及有效期上限：[mqtt_v4.c:70](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:70)；字段校验：[abox_mqtt_request.c:78](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/mqtt/src/abox_mqtt_request.c:78)；执行准入：[wing_controller.c:547](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/wing_controller.c:547)。

### 2.3 同步当前状态

发布到 `B/request`，`command=sync_state`、`params=null`，不携带 expiresAt。其作用是取得当前状态快照，不会主动启动或停止机构；空闲会话不轮询 CAN，因此快照可能显示 statusFresh=false，并不承诺获得一次新的下位反馈。

```json
{
  "version": "4.0",
  "timestamp": 1793584802000,
  "data": {
    "requestId": "wing-sync-001",
    "command": "sync_state",
    "params": null
  }
}
```

响应成功时，result.expectedStates 列出 `wing_status`。平台需等待同一 requestId 的完整状态，响应和报告可能乱序；只收到 200 尚不算收齐。调度代码：[mqtt_v4.c:214](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:214)、[mqtt_v4.c:475](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:475)；公共分类校验：[abox_mqtt_request.c:106](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/mqtt/src/abox_mqtt_request.c:106)。

## 3. 公共上传报文

### 3.1 response：请求处理结果

设备发布到 `B/response`，通过 requestId 关联。升降的 200 表示已接受动作，不表示到达目标；stop 的 200 表示取得了停止反馈。不要用 MQTT 的发布确认代替业务响应或机械停止确认。

```json
  "timestamp": 1793584800500,
  "data": {
    "requestId": "wing-up-001",
    "code": 200,
    "msg": "operation accepted"
  }
}
```

### 3.2 wing_status：完整业务状态

发布到 `B/report`，reportType=state。启动、重连、同步，以及动作/停止/端点/故障等状态变化时发送。requestId 仅在关联具体请求时出现，自动状态变化可能省略。

```json
{
  "version": "4.0",
  "timestamp": 1793584800600,
  "data": {
    "reportId": "wing-status-001",
    "reportType": "state",
    "reportName": "wing_status",
    "requestId": "wing-up-001",
    "payload": {
      "motionState": "ascending",
      "activeAction": "ascend",
      "positionMm": 126,
      "topLimitMm": 250,
      "bottomLimitMm": 1,
      "atEndpoint": null,
      "faultCode": null,
      "controllerOnline": true,
      "statusFresh": true,
      "safetyStopReason": null
    }
  }
}
```

| payload 字段 | 作用 |
| --- | --- |
| motionState | unknown/stopped/ascending/descending/moving_unknown/fault/offline |
| activeAction | 当前活动升降动作，无活动动作时 null |
| positionMm | 当前位置，毫米，未知为 null |
| topLimitMm / bottomLimitMm | 上下限位置，毫米，未知为 null |
| atEndpoint | top/bottom/null |
| faultCode | E 加两位数字形式的故障码，无已知故障为 null |
| controllerOnline | true/false/null，null 表示无法判断 |
| statusFresh | 状态是否基于有效反馈，平台判断停止和完成必须关注此字段 |
| safetyStopReason | feedback_timeout/max_runtime/controller_fault/null |

当前公共 payload 恰好为上述 10 个字段，不包含 CAN 会话调试字段、超声波八路距离、障碍 mask、防夹输入或声光报警输出状态。若新平台需要独立显示这些信息，需要另行设计并实现字段，不能假定已存在。字段组装：[mqtt_v4.c:341](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:341)；报告封装：[mqtt_v4.c:368](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:368)；上报调度：[mqtt_v4.c:411](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/mqtt_v4.c:411)。

## 4. 内部授时：新平台正常升降所必需

设备在 TLS MQTT 连接就绪后向 `B/internal/time/request` 请求授时；平台必须回到 `B/internal/time/response`，原样回显本次 requestId。

设备→平台：

```json
{
  "version": "2.0",
  "timestamp": 1793584800000,
  "data": {
    "requestId": "ts-0000000000000001-1",
    "command": "sync_time",
    "params": {}
  }
}
```

平台→设备：

```json
{
  "version": "2.0",
  "timestamp": 1793584800000,
  "data": {
    "requestId": "ts-0000000000000001-1",
    "code": 200,
    "result": {
      "serverUtcMs": 1793584800000,
      "errorMs": 50
    }
  }
}
```

serverUtcMs 为服务器发布响应前采样的 UTC 毫秒；errorMs 是实际参考误差界，不能为了通过检查虚报。当前要求服务器误差界不超过 250 ms、RTT 不超过 800 ms，设备计算的可信误差上限为 500 ms。采样器每批尝试 3 次并选择合格样本，随后按误差预算刷新；不能只在开机回应一次。未授时或授时失去可信度时，公开上报 timestamp 可为 0，新升降拒绝，stop/sync_state 不因授时未就绪而被拒绝。4G 模组 CCLK 只提供启动时间基础，不能代替平台可信授时。

TLS 就绪门控和产品入口：[time_sync.c:40](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/app/Core/User/Src/time_sync.c:40)；报文与回包解析：[abox_time_client.c:5](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/cloud/src/abox_time_client.c:5)、[abox_time_client.c:56](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/cloud/src/abox_time_client.c:56)；采样：[abox_time_sync.c:6](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/core/src/abox_time_sync.c:6)；误差阈值：[abox_clock.h:21](E:/1_work/Ding_Fei_Yi/TopFlyingWing_Latest_Merged_20261030/platform/components/core/include/abox_clock.h:21)。

## 5. 内部运维报文

### 5.1 internal_config

发布到 `B/internal/config`，响应从 `B/internal/config/resp` 返回。外层 version=2.0，command=internal_config，具体操作由 params.action 选择。当前接收分支支持以下 action；不能仅因库中存在其他函数就认为已对外开放。

| action | 作用 | 其他主要参数 |
| --- | --- | --- |
| get_info | 查询固件/Boot、MQTT、可信时间、OTA 等诊断信息 | 无 |
| get_log | 获取内存日志片段，result 为字符串 | 无 |
| clear_log | 清空内存日志 | 无 |
| reboot | 受控复位 | 无 |
| set_mqtt | 新 TLS Broker 配置试连、确认后保存，失败恢复旧配置 | vid、host、port、username、password、tlsEnabled、tlsProfileId |

get_info 示例：

```json
{
  "version": "2.0",
  "timestamp": 1793584800000,
  "data": {
    "product": "top_flying_wing",
    "requestId": "info-001",
    "command": "internal_config",
    "params": {
      "action": "get_info"
    }
  }
}
```

get_info 的 result 包含 vid、product、fwVersion、bootVersion、bootDescriptorValid、bootApiVersion、bootFeatures、otaScheme、otaDownloader、stableSeedSource、otaBootstrapNeedsRevision、otaState、otaPhase、otaReady、otaBusy、mqttHost、mqttPort、mqttTls、mqttTlsActive、mqttTlsProfileId、mqttAuthMode、maintenanceProtocols、trustedTime、canBus、canBitrate、feedbackTimeoutMs、canSessionMode，不返回账号密码。

set_mqtt 示例（迁移时先保持现有 VID）：

```json
{
  "version": "2.0",
  "timestamp": 1793584800000,
  "data": {
    "product": "top_flying_wing",
    "requestId": "mqtt-change-001",
    "command": "internal_config",
    "params": {
      "action": "set_mqtt",
      "vid": "TFW000001",
      "host": "mqtt.example.com",
      "port": 8883,
      "username": "platform_user",
      "password": "REPLACE_WITH_SECRET",
      "tlsEnabled": true,
      "tlsProfileId": 0
    }
  }
}
```

该事务要求当前与候选连接均为 TLS，并在空闲等准入条件下执行。202 表示开始试连；完成新 Broker 订阅、关联心跳与配置保存/读回后才返回 200；失败尝试回到旧配置并返回失败。成功终态响应可能从新 Broker 发出，因此迁移平台必须同时关注旧/新连接。不能把 202 当作切换成功，也不要先关闭旧平台再发迁移命令。当前配置存储 VID/用户名/密码数组均为 32 字节，实际可用最长 31 字节；host 最长 63 字节。tlsProfileId 在该 MQTT 请求中是数字 0。

## 6. HTTPS 入网报文

设备没有有效持久化 MQTT 凭据时，使用独立 HTTPS 入网服务；已有有效凭据的设备直接沿用 Flash 配置，不会因为改默认宏就切换平台。

当前 origin：`https://zxwl.ntiov.com:20444`。

新申请：`POST /api/v1/enroll/abox/requests`，JSON body：

```json
{
  "uid": "00112233445566778899AABB",
  "iccid": "89860000000000000000",
  "vid": "TFW000001",
  "hardwareContract": "top_flying_wing_stm32f105_ec800_v1",
  "bootVersion": "abox-boot-2.3.0",
  "appVersion": "top-flying-wing-1.1.8"
}
```

服务器 200/201 返回 requestId、pollToken，可附 retryAfterSec。之后设备轮询 `POST /api/v1/enroll/abox/requests/{requestId}/poll`，body 为 `{"pollToken":"EXAMPLE_TOKEN"}`；审批中返回 202，批准后返回 200 和如下结构：

```json
{
  "requestId": "enroll-001",
  "status": "approved",
  "vid": "TFW000001",
  "mqtt": {
    "host": "mqtt.example.com",
    "port": 8883,
    "username": "platform_user",
    "password": "REPLACE_WITH_SECRET",
    "tlsEnabled": true,
    "tlsProfileId": "0"
  }
}
```

注意这里 MQTT 凭据中的 tlsProfileId 按当前入网解析器要求为字符串 "0"，与 set_mqtt 的数字 0 不同。该产品使用 CA 模式；通用库的 PSK 分支并不表示本产品已接受 PSK 入网。设备需要完成首次 MQTT 试连、订阅及心跳确认，再保存并读回配置。

## 8. 当前实现必须保留的对接语义

- 消息总大小不超过 1024 字节，params/result/payload 的规范化值大小上限为 768 字节；不使用分片。
- 新升降操作使用新 requestId；同一次网络重试保留原 requestId、内容和有效期，避免重复动作。
- 当前持久化升降去重记录只有 9 条，保护至 expiresAt 后 10 分钟。短时间频繁操作会耗尽容量并返回 4003；更换平台本身不会消除该限制，不应通过清空记录规避。
- stop 是独立安全操作，不因未授时被拒绝；改变方向仍需先 stop 并收到新鲜停止确认。
- sync_state 返回当前快照，不能把缓存位置或 statusFresh=false 当作当前已停止的证据。
- 心跳只证明 A-BOX 通信在线；200 只满足相应请求的成功边界，不自动表示到达端点或真实运动成功。
- 位置 telemetry 只用于显示趋势，完整状态 state 用于业务判定；按 reportId 去重并处理响应/报告乱序。
- 当前代码没有独立的远程“打开/关闭声光报警”命令，也没有公共的超声波原始距离、防夹输入、报警灯状态字段；相应联动在设备本地执行。
- 目录中的 V3 文档及遗留诊断配置字段不代表当前固件的活动下控入口。已连接的公共下控入口是 V4 request；当前日志上传入口是 internal/log。
