# 顶飞翼 V1 / V2 硬件适配

内部资料，不作为业务对接协议交付。

V1 使用 GD32F105RCT6，V2 使用 STM32F105RCT6。产品身份始终为 `top_flying_wing`；两种目标使用不同的 MCU 版本标记和入网硬件合同。公共平台 `stm32f105_ec800_v1` 的历史名称不表示 PCB V1。

- V1：`ABOX_BOARD_VERSION=v1`，App 版本须以 `-gd` 结尾；使用公共 GD 板级启动、Flash、EC800、时基和 CAN 实现。`tools/build_gd_candidate.ps1` 在 `build/wing-gd-candidate` 分别构建 App 和公共 GD Boot，并验证 Boot 描述符与 App 标记；不生成正式包。
- V2：`ABOX_BOARD_VERSION=v2`，App 版本须以 `-st` 结尾；沿用产品 STM32 启动和冻结 STM32 Boot。正式打包只接收冻结 STM32 Boot，拒绝 GD App。
- 两种 App 的起始地址为 `0x08008000`，最大 216 KiB；`0x0803E000` 为配置恢复页，Boot State A/B 和配置页保持原地址。OTA 启动、稳定槽播种和就绪状态需要匹配当前 MCU 的 Boot 描述符；运行中的 GD App 只接受 `-gd`，ST App 接受 `-st` 或历史无后缀版本。
- 公共 CAN1 用于 WL300D，按构建配置选择 250 或 500 kbit/s；CAN2 用于飞翼控制器，500 kbit/s。方向改变仍由产品状态机先发送 stop 并等待已停止反馈。V1 防夹接 B8（PA4），V2 接同一 B8（PA7）；使用 1 ms 中断采样及既有消抖。OUT1 为报警输出，OUT2/3 为电源输出。
- GD 入网合同为 `top_flying_wing_gd32f105_ec800_v1`，需服务端注册表支持后才能首次入网；ST 保留原合同。App OTA 不更新 Boot。既有 GD 板如仍使用 STM32 Boot，需要单独安排可恢复的线刷迁移，不能仅凭新 App 判定 OTA 可用。

产品主机测试和两种 ARM 交叉构建只覆盖源码行为。V1/V2 上电、B8 极性、双 CAN 收发、真实停止反馈、断电恢复及 OTA 安装/回滚均需分别在对应板卡和安全条件下验证；未验证的硬件行为不得据构建结果声称完成。
