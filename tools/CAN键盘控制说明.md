# top_flying_wing CAN 键盘台架控制

内部台架工具，不作为业务对接协议对外交付。

## 连接与启动

1. 驱动器保持其电机、霍尔及自身限位接线。断开 A-BOX 到该驱动器的 CAN 连接，避免两个主控同时发送命令；本脚本不读取 A-BOX 防夹条，不代替已有防夹联动。
2. CAN 分析仪 CH1_H 接驱动器 CAN_H，CH1_L 接 CAN_L，按设备要求连接参考地及终端。关闭其他占用分析仪的软件。
3. 使用 64 位 Windows Python。此电脑可直接双击同目录的 `run_can_keyboard.cmd`；也可以在仓库根目录运行：

```powershell
& D:/Anaconda-3/python.exe -B tools/can_keyboard.py
```

默认使用此电脑已有的厂家 64 位 DLL：`E:/canalyst-II-Driver/CAN/二次开发库文件/x64(64bit)/ControlCAN.dll`。没有额外 Python 包依赖。更换电脑时可指定路径：

```powershell
python -B tools/can_keyboard.py --dll "C:/CAN/ControlCAN.dll" --channel 1
```

工具使用 CH1、500 kbit/s、扩展数据帧、请求 ID 1、DLC 8。默认应答 ID 也是 1，与已验证项目 `E:/1_work/abox-top-wing` 的实现保持一致；不再自动识别 ID。若实物使用应答 ID 2，可明确指定 `--rx-id 2`。总线须只有一台对应请求 ID 的驱动器。

普通键盘模式启动后显示 `idle`，保持 CAN 静默，不自动查询或运动；这里的 `idle` 仅指软件空闲，不代表驱动器已在线。按 W/S 后才依次发送 RD，取得已停止且无故障反馈，静默等待 250 ms，再发 RD，再次确认停止后发 RL。只有上下限有效、位置在范围内且未到请求方向的安全边界，才发一次 UP 或 DN。

RD/RL 查询应答超时为 300 ms，命令应答超时为 1 秒；不在应用层重发查询或运动指令。查询失败会尝试 ST 并锁定升降。没有应答、零行程、限位无效、故障或仍在运动时均不放行，不会在启动或恢复后自动上升／下降。

## 按键

保持脚本控制台接收键盘输入：

| 按键 | 行为 |
|---|---|
| W | 预检通过后发一次 UP，向上运行；到最高限位减安全余量时提交 ST |
| S | 预检通过后发一次 DN，向下运行；到最低限位加安全余量时提交 ST |
| 空格 | 立即提交 ST，取消待执行换向，等待应答及 RD 停止反馈 |
| ESC | 停止确认后退出；停止失败明确报错退出 |
| Ctrl+C | 尝试停止并读取确认，然后退出 |

这是按一次持续运行的控制方式，松键不停止。长按产生的 Windows 自动重复按键会被抑制；到限位不会因仍按住 W/S 重复启动，须松开再重新按下。空格／ESC 在同一批输入中优先于 W/S。收到控制台失焦事件时停止，重新获得焦点不会自动恢复；部分终端不提供完整焦点事件，不能把失焦视为可靠急停方式。

运行中按相反方向，程序先明确发送 ST，得到 ST 应答和 RD 已停止且无故障反馈后，再执行 RD、250 ms 静默、RD、RL 预检，才发相反方向的 UP/DN。换向等待期间按空格取消反向意图。故障锁定后 W/S 无效；空格重新执行 ST 应答与 RD 停止确认，成功后回到空闲，不自动恢复运动。下一次 W/S 仍须重新查询限位。脚本文件更新后，已经打开的旧进程需退出并重新启动才会加载新代码。

## 与已验证项目一致的报文顺序

普通上升：`RD → 已停止反馈 → 等待250ms → RD → 已停止反馈 → RL → 有效限位 → UP → UP应答 → RD → 运动反馈`；下降将 UP 换成 DN。运行中约每 100 ms 查询 RD，空闲时不轮询，运行中不额外查询 RL。

所有请求 ID 都是 `0x00000001`，扩展数据帧、DLC 8，数据如下：

| 命令 | 数据（十六进制） |
|---|---|
| RD | `52 44 00 00 00 00 00 00` |
| RL | `52 4C 00 00 00 00 00 00` |
| UP | `55 50 00 00 00 00 00 00` |
| DN | `44 4E 00 00 00 00 00 00` |
| ST | `53 54 00 00 00 00 00 00` |

停止顺序为 `ST → ST应答 → RD → 已停止反馈`。脚本不发送 HELLO、RS 或 MO。限位保护、停止确认及换向保护继续有效，不会因为模仿正常收发顺序而跳过这些检查。

## 霍尔位置与限位

脚本使用厂家提供的 RD 位置（mm）及 RL 上／下限。PC 无法从本协议直接访问每根杆的原始霍尔脉冲。

默认安全余量为 **2 mm**：

- W 发 UP，RD 位置达到 `top-2` 时提交 ST；S 发 DN，RD 位置达到 `bottom+2` 时提交 ST。这里的 2 mm 是 PC 软件停止阈值，不是发送给驱动器的 MO 目标。
- 每次运动前，两次 RD 确认停止，中间保持 250 ms；再读 RL，位置、故障、限位和余量有效后才发送一次 UP/DN。
- 运动期间约 100 ms 查询 RD，使用本次运动开始前读取的限位；下次运动重新读取 RL。
- 到达安全边界、位置超范围、反馈明显反向、驱动器故障、反馈超过 500 ms 未更新、应答超时或连续运动达到 120 秒时，提交停止并检查结果。
- 未经停止确认不会声称机构已经停止。故障不会自动恢复运动。

可以调整保守余量和最长运行时间：

```powershell
python -B tools/can_keyboard.py --margin-mm 5 --max-run-seconds 120
```

程序使用的上／下限来自驱动器已保存的配置，不会修改或标定限位。首次使用前须确认驱动器的限位已按机构实际行程正确设定。厂家文件说明 RD 可能是多根杆的平均位置，无法凭该值证明每根杆都没超限；软件查询周期、制动距离、霍尔误差也会影响实际停止位置。驱动器自身限位和机械／硬件停止保护仍须有效，不能宣称本工具保证零超调。

## 故障与记录

CAN 库采用正常总线模式，发送帧使用厂家要求的多节点正常发送方式（`SendType=0`），不使用自发自收。厂家说明：发送失败时分析仪最多重试 1 秒，超时取消；脚本不会在应用层重复提交 UP/DN 运动命令。底层重试及总线故障可能延迟停止命令，DLL 返回 1 不能代替应用应答及真实状态确认。

日志保存到仓库 `build/app/can_keyboard_日期_时间.jsonl`，含原始 TX/RX、应答 ID、位置、限位、软件停止边界、停止及故障原因。窗口同时显示 TX/RX 十六进制数据，便于核对先后顺序。

故障时 `can_statistics` 显示累计提交帧数及收到的全部 ID 帧数。`no_rx` 表示没有收到任何帧，不是仅丢弃了其他 ID 的报文。`RD response timeout` 表示未取得有效状态应答；它不等于键盘没有响应。

可以运行不读取键盘、只发送查询和停止的诊断模式：

```powershell
python -B tools/can_keyboard.py --probe-only --probe-seconds 5
```

诊断模式执行 `RD → 250ms → RD → RL` 查询，结束时尝试 ST 与 RD 停止确认；不会发送 UP 或 DN。读取不到应答时返回失败，不会把 DLL 接受提交当成驱动器通信正常。

关闭窗口、强制结束进程、USB 断开、断电或总线故障可能使停止命令无法送达。若程序提示 `STOP NOT CONFIRMED`，必须使用驱动器的物理停止措施。此前这块板的 CAN 抓包未取得有效帧，本工具也不会绕过反馈门禁强行运动。
