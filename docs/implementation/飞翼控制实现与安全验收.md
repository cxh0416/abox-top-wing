# 飞翼控制实现与安全验收

本文档面向固件开发、硬件联调和现场验收，不属于公共平台协议。平台对接只需阅读 `docs/protocols/A-BOX飞翼设备业务协议-V4.0.md`。

当前源码构建标识：`top-flying-wing-1.1.0`

## 1. 硬件反馈边界

控制器可返回命令接受/拒绝、多推杆平均位置、运动/停止状态和 E01～E16 故障码，不能直接返回运动方向、电流、电压、温度、单根推杆位置或机械动作完成原因。

固件根据已接受且未取消的远程动作推断 `ascending` 或 `descending`；无法可靠确定方向时使用 `moving_unknown`。完全空闲时不主动轮询控制器，诊断扩展字段可表现为 `canSession=idle_silent`、`statusFresh=false`、`controllerOnline=null`。

## 2. 控制流程

1. 新的升降请求先执行两次运动检查，两次之间静默 250 ms，再读取限位。
2. 发现现场运动、查询超时、故障或限位非法时拒绝远程升降。
3. 预检通过后只发送一次 `UP` 或 `DN`，远程运行期间周期读取状态。
4. `stop` 可以抢占预检、启动和远程运行；空闲时的显式停止也调用同一停止确认流程。
5. `stop` 只有取得控制器接受和 `stopped` 反馈后才返回成功并清除动作锁存。
6. 到达目标端点、反馈超时、控制器故障、连续运行达到上限、位置反向或未到端点意外停止时，只触发一次停止流程收口。
7. 相同 `requestId`、相同请求内容的重复投递只返回首次响应，不重复下发控制。

## 3. 安全行为

- 反馈超时：尽力停止，并报告 `safetyStopReason=feedback_timeout`。
- 达到最长连续运行时间：停止确认后报告 `safetyStopReason=max_runtime`。
- 控制器故障：尽力停止，并保留原始故障码。
- MQTT 断开：不取消已经接受的动作，控制器监测和运行上限计时继续。
- 未取得停止确认：不得宣称机械已经停止。
- 方向切换：必须经过独立的停止请求和停止确认，不在升降命令中隐式换向。

反馈超时和最长运行时间属于设备配置，不通过公共业务协议修改。

## 4. 诊断扩展字段

当前固件状态报文还可能包含以下诊断字段，供设备维护和问题定位使用，平台基本业务不得依赖：

| 字段 | 当前含义 |
|---|---|
| `canSession` | `idle_silent`、`preflight`、`remote_running`、`stopping` 或 `fault` |
| `controlOwner` | `none`、`remote` 或 `local_suspected` |
| `operationPhase` | 当前内部控制阶段 |
| `feedbackAgeMs` | 最近有效控制器反馈年龄 |
| `runElapsedMs` | 本轮连续运动计时 |

## 5. 控制器故障码

| 故障码 | 含义 |
|---|---|
| `E01` | 遇阻回退 |
| `E02` | 同步偏差告警 |
| `E03` | 欠压警告 |
| `E04` | 倾斜警告 |
| `E05`～`E08` | 对应通道过流 |
| `E09` | 电源过流 |
| `E10`～`E13` | 对应通道霍尔无信号 |
| `E14` | 过热警告 |
| `E15` | 密码或注册错误 |
| `E16` | 异常断电报警 |

具体诊断和处置以厂家控制器资料及现场检测结果为准。

## 6. 验收边界

- 构建、单元测试和 MQTT 响应只能证明软件及接口行为。
- OTA 接受响应不能单独证明安装成功，应核对实际运行版本和 Boot 确认状态。
- MQTT 状态不能单独证明真实机械运动，升降、端点和现场控制冲突必须在安全条件下进行硬件验收。

## 7. V4 通信适配边界

- 平台依赖固定为 `d799d0c`。公共请求 Decode/Resolve、SHA-256/JCS、Topic、有效期、EC800 MQTT/TLS、V4 报文编码、Cloud 启动顺序、重连退避与内部授时直接链接平台组件；产品侧维护 `wing 1.0` 参数匹配、控制器适配、事务关联和业务 payload。公共 Boot 二进制继续使用原冻结产物。
- 顶飞翼不新增 `0x0803E000` 配置恢复页；发布复用本仓库的冻结契约校验，保持 App 末端为 `0x0803E7FF`，不能套用其他产品的恢复页默认布局。
- 升降预检、250 ms 静默、100 ms 反馈轮询、端点/冲突/故障/超时安全停止及单次停止收口保持原流程。控制器新增的观察接口只保存生成时快照和请求关联；只有“空闲显式停止”补齐原有停止确认流程，不再直接成功。
- 控制请求 ID 容量为 64 个 ASCII 字符。报告保存确认时的不可变快照，避免进入空闲静默后把已取得的停止反馈丢掉；快照和结果的复制使用短临界区。
- 新升降请求统一使用 `abox::mqtt_idempotency`、`abox::mqtt_idem_ufs`、`abox::ec800_ufs_at` 和 `abox::ufs_journal`。固定文件 `UFS:wing-v4-idem-a.bin` / `UFS:wing-v4-idem-b.bin` 使用公共 `A4J1` / `M4I1` 格式；9 个记录槽，每条完整响应容量 256 字节。PREPARED 双副本写入并回读后才允许一次派发，最终完整响应双副本提交后才进入发送队列；重投直接重放保存的原始响应。跨重启保护、容量回收、提交/恢复和损坏判定均由公共组件维护。
- 文件命名空间固定绑定 MCU 身份；传给公共幂等表的请求键为 `SHA-256(deviceId + NUL + requestId)` 的 64 字符十六进制文本。公共逻辑摘要仍由平台生成，响应保留原始公共请求 ID。这样 VID 试用和回退使用同一物理日志，同时保持不同 Topic 身份的请求隔离。改号取消尚待派发的旧意图，旧身份的最终记录正常完成持久化，不把旧响应发送到新身份 Topic。
- 配置页主体及边界不变，原 `OTA_Info_t.reserved[0]` 作为独立 UFS 首次使用标记；普通配置保存和清理保留该字。仅在双副本均明确不存在且标记为擦除态时初始化新日志，部分标记不视为首次使用。已初始化后双副本均丢失、损坏或事务失败时，本次启动禁用新升降；停止、状态同步、心跳与内部维护继续可用。模组 RDY 不清除失败状态。维修应核对并恢复已有保护记录，不能将删除日志或擦除标记作为普通重试步骤。
- 原配置页尾部从偏移 512 开始的 9 个 168 字节 Flash 槽只读，不再写入新请求；有效旧记录继续处理重放、冲突和重启不确定性，损坏旧记录拒绝新升降。受保护的旧槽仍阻止配置页擦除，保护期结束后才按原配置保存路径回收，避免升级时抹去旧请求保护。
- UFS 与 OTA 共用 3336 字节工作区，由单个事务租用。只在 MQTT READY 且 AT 空闲时借用，事务持有期间 OTA 下载/初始化、长重连、配置停连及新的 MQTT 发布暂缓；CAN 控制任务和收到的停止请求仍运行。工作区及公共引擎的显式初始化状态放在现有 `.ota_work`，保持 `0x2000BC40` 故障邮箱、8 KiB 最低堆和 4 KiB 最低栈，不另分配一份日志快照。
- 停止及 Core 查询不进入持久离散动作队列。等待落盘的升降意图可被停止或改号取消；异步等待后由 `TakeExecutable` 重查可信时间和有效期，不能在旧请求过期后派发。UFS 实际写入/回读时延和寿命需在目标 EC800 固件上验证，特别关注 5 秒有效期内的准备耗时。
- 公共 TLS 使用模组实际探测到的上下文 2，HTTPS OTA 继续保留上下文 1；复用已核验的 `UFS:ota_ca.pem`，启用证书验证、SNI 和时间检查。配置试用只在匹配响应确认后开始，只有新连接心跳确认后才保存，失败恢复原配置。
- 内部授时报文与连接代次隔离统一使用 `ABoxTimeClient`，复用公共三样本、RTT/误差约束和时钟质量模型。CCLK 只作启动时间；业务有效期使用可信时钟并在持久预留后再次检查。单调时钟复用平台 TIM2 实现，保持原控制超时与周期数值，避免 Flash 操作阻断普通 HAL tick 时丢失经过时间。

主机回归覆盖原控制与安全流程、空闲停止及端点换向、公共 UFS 准备/最终提交、原始响应重放、单副本恢复/双副本丢失、等待期间停止/过期/改号、旧 Flash 兼容、资源租用与重连退避、报告 QoS/关联、TLS 授时代次和配置回退。它们不替代真实模组、Broker、机械及 OTA 验收。
