# 车载 A-BOX 设备对接协议

文档版本：V2.1 修订稿
报文版本：V2.0
修订日期：2026-08-21

> 本文档定义车载 A-BOX 与业务平台之间的公共 MQTT 业务协议。文档版本升级不改变报文外层的 `version: "2.0"`。

---

## 1. 文档说明

### 1.1 文档用途

本文档为车载 A-BOX 设备与业务平台对接通信协议，定义双方 MQTT 通信主题、统一消息报文、指令交互流程和设备数据上报格式，作为嵌入式设备、后端开发、测试人员对接开发的统一标准依据，仅适用于 A-BOX 设备对接。

### 1.2 保密声明

1. 未经本公司书面许可，禁止复制、转发、外传本文档全部或部分内容。
2. 文档内接口、Topic 和报文格式属于项目私有技术方案，受知识产权保护。
3. 文中设备 ID、UUID、时间戳均为测试示例，无实际业务关联。

### 1.3 对接前置信息

平台应提供：

- MQTT Broker 地址和端口；
- MQTT 用户名和密码；
- 全平台唯一的 `deviceId`；
- 设备对应的 `product`。

`deviceId` 由平台分配并固化到设备中，不得重复。

### 1.4 基础前置约定

1. 所有 MQTT 消息均为标准 JSON，编码为 UTF-8。
2. 固定 Topic 段使用小写；`deviceId` 按平台分配值原样插入。
3. `deviceId` 仅允许字母、数字、下划线和连字符，且在全部 A-BOX 产品中不得重复。
4. `timestamp` 为 UTC Unix Epoch 毫秒时间戳，使用 JSON 整数，由发送端在发送时生成。
5. 所有请求、响应、心跳和状态上报的 `data` 对象都必须包含 `product`。

### 1.5 MQTT QoS 约定

| 消息类型 | QoS | Retain | 说明 |
|---|---:|---:|---|
| 平台下发请求 | 1 | 否 | 至少一次送达，设备必须按 `requestId` 去重 |
| 设备请求响应 | 1 | 否 | 返回处理结果 |
| 设备心跳 | 0 | 否 | 每 5 秒上报，允许少量丢失 |
| 设备主动状态 | 1 | 是 | 保留最新业务状态；运动过程、状态变化、故障和安全停止统一上报 |

### 1.6 心跳、遗嘱与离线判定

1. 设备每 5 秒发布一次心跳。
2. 平台连续 15 秒未收到设备心跳时，判定 A-BOX 离线。
3. 设备可配置 MQTT 遗嘱消息；遗嘱属于连接异常的辅助通知，平台最终仍以心跳超时判定离线。
4. A-BOX 在线与下游业务控制器在线是两个独立状态。对于顶飞翼，A-BOX 在线但 `controllerOnline=false` 时，平台应显示 A-BOX 在线、飞翼控制器离线。
5. 平台离线判定以心跳接收时间为准，不使用设备时间戳替代 Broker 接收时间。

### 1.7 兼容性约定

1. 报文外层固定包含 `version`、`timestamp` 和 `data`，不得增加与 `data` 平级的业务字段。
2. 新增业务字段只能放在 `data` 或 `data.result` 内。
3. 接收方必须忽略 `data` 中无法识别的扩展字段，不得因此拒绝整个报文。
4. 平台收到无法识别的状态枚举值时，必须保存原始值，并按 `unknown` 降级展示；不得因此丢弃整条状态消息。
5. 设备收到无法识别的 `command` 时返回 `4002`；收到已知命令但无法识别的动作或参数枚举时返回 `4001`。
6. 报文外层 `version` 在本修订稿中固定为字符串 `"2.0"`。
7. 新增产品、新增命令或新增可忽略字段属于兼容扩展，继续使用 `version="2.0"`。
8. 修改既有字段的名称、类型、必填性或业务含义属于破坏性变更，必须升级报文主版本（例如 `3.0`）；不得继续声明为 `2.0`。

### 1.8 适用产品与阅读路径

`product` 表示设备产品类型，不表示购买方、客户或项目。购买方和项目归属由平台按照 `deviceId` 维护，不得通过派生新的 `product` 区分。

| 产品 | `product` 固定值 | 支持的公共命令 |
|---|---|---|
| 送餐车 | `meal_delivery_vehicle` | `open_locker`、`check_locker_status` |
| 顶飞翼 | `top_flying_wing` | `wing_control`；状态由设备主动上报 |

设备必须固化自身 `product`。请求中的 `product` 与设备固化值不一致时，设备返回 `4004`，不得执行命令。

建议按以下路径阅读，避免把某一产品的业务语义套用到另一产品：

| 角色或范围 | 必读章节 |
|---|---|
| 所有设备端、平台端 | 第 1～3 章、第 6 章 |
| 送餐车格口业务 | 第 4 章 |
| 顶飞翼业务 | 第 5 章、第 7 章 |

当前只有顶飞翼定义 `/status/report`；未来产品可在自身产品章节中声明使用该 Topic 和对应状态结构。E01-E16 故障码仅属于顶飞翼，不适用于送餐车格口业务。

### 1.9 新产品扩展规则

1. 一台 A-BOX 固化一个 `deviceId` 和一个 `product`。同时包含多种业务功能的整机作为一种新产品登记，不在同一报文中携带多个 `product`。
2. `product` 使用稳定的 `snake_case` 标识并匹配 `^[a-z][a-z0-9_]*$`，表示产品类型，不得包含客户、购买方、地区或项目名称。
3. 新产品的控制请求优先复用 `/ctrl`、`/ctrl/resp`，按需状态查询复用 `/status`、`/status/resp`，心跳复用 `/heartbeat`；需要主动状态上报时复用 `/status/report`，不得仅因产品不同新增一套公共 Topic。
4. 新产品必须在本文档中登记产品标识、支持命令、请求参数、响应结果、响应码语义，以及可选的主动状态结构。
5. 命令和响应码必须结合 `product` 解释；新增产品不得改变既有产品的命令或响应码含义。

### 1.10 协议边界

本文档仅定义公共业务协议。设备配置、设备信息、远程日志和 Boot V2 OTA 使用独立的 A-BOX 内部运维协议及 `/internal/*` Topic，不在本文档中定义。

## 2. 消息格式规范

### 2.1 通用消息头

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "top_flying_wing"
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `version` | String | 是 | 报文版本，固定为 `2.0` |
| `timestamp` | Integer | 是 | UTC Unix Epoch 毫秒时间戳 |
| `data` | Object | 是 | 业务数据对象 |
| `data.product` | String | 是 | 固化的产品标识 |

### 2.2 平台请求结构

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "top_flying_wing",
    "requestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "command": "wing_control",
    "params": {
      "action": "stop"
    }
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `product` | String | 是 | 目标产品标识 |
| `requestId` | String | 是 | 平台生成的全局唯一请求标识，设备响应时原样返回 |
| `command` | String | 是 | 业务命令 |
| `params` | Object / null | 是 | 命令参数；无参数时固定传 `null` |

### 2.3 设备响应结构

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "top_flying_wing",
    "requestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "code": 200,
    "msg": "操作成功",
    "result": null
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `product` | String | 是 | 设备固化的产品标识 |
| `requestId` | String | 是 | 对应请求的 `requestId` |
| `code` | Integer | 是 | 处理结果码 |
| `msg` | String | 是 | 结果描述 |
| `result` | Object / null | 是 | 业务结果，无结果时为 `null` |

### 2.4 响应码阅读规则

响应码分为公共响应码和产品专用响应码。平台必须先根据 `data.product` 和 `command` 确定业务，再解释响应码；不得把顶飞翼控制错误码套用到送餐车格口业务。

#### 2.4.1 公共响应码

| 响应码 | 适用范围 | 说明 |
|---:|---|---|
| `200` | 全部产品 | 请求处理成功；成功边界由对应产品章节定义 |
| `400` | 已定义该码的业务命令 | 业务执行失败；失败详情由对应产品章节定义 |
| `4001` | 全部产品 | 参数非法，或同一 `requestId` 对应了不同请求内容 |
| `4002` | 全部产品 | 当前产品不支持该命令 |
| `4003` | 全部产品 | 业务资源繁忙；具体占用条件由对应产品章节定义 |
| `4004` | 全部产品 | 请求 `product` 与设备固化产品不一致 |
| `500` | 全部产品 | 响应无法在产品规定的单包上限内完整生成，设备返回紧凑错误响应且不得截断业务数据 |
| `5001` | 全部产品 | A-BOX 内部异常 |

#### 2.4.2 响应码归属索引

| 产品 | 响应码范围 | 详细定义 |
|---|---|---|
| 送餐车 `meal_delivery_vehicle` | 公共码；其中 `200`、`400`、`4003` 按格口语义解释 | 第 4.1 节 |
| 顶飞翼 `top_flying_wing` | 公共码及顶飞翼专用码 `5002`～`5005` | 第 5.4 节 |

未在当前产品章节中列出的响应码视为协议实现错误，平台应记录原始报文，不得自行猜测其业务含义。

### 2.5 产品校验和命令隔离

设备收到请求后按以下顺序校验：

1. 校验 JSON、通用字段和参数，失败返回 `4001`。
2. 校验 `product`，不一致返回 `4004`。
3. 校验当前产品是否支持 `command`，不支持返回 `4002`。
4. 校验 `requestId` 去重结果。
5. 进入具体业务处理。

### 2.6 QoS 1 请求去重

1. 设备必须缓存最近处理过的 `requestId`、请求摘要和完整响应。
2. 相同 `requestId` 且请求内容相同：返回首次处理的完整响应，不重复执行业务或下发底层控制指令。
3. 相同 `requestId` 但请求内容不同：返回 `4001`，不得执行新请求。
4. 去重缓存应覆盖 MQTT 重连和平台常规重试窗口；具体容量和持久化方式由固件实现确定，但不得改变上述对外行为。

## 3. MQTT Topic

Topic 中的 `{deviceId}` 替换为设备唯一标识。

| 方向 | 用途 | Topic | 适用产品 |
|---|---|---|---|
| 平台 -> A-BOX | 控制请求 | `/zxwl/abox/{deviceId}/ctrl` | 全部产品 |
| A-BOX -> 平台 | 控制响应 | `/zxwl/abox/{deviceId}/ctrl/resp` | 全部产品 |
| 平台 -> A-BOX | 按需状态查询 | `/zxwl/abox/{deviceId}/status` | 按产品章节定义；当前仅送餐车 |
| A-BOX -> 平台 | 状态查询响应 | `/zxwl/abox/{deviceId}/status/resp` | 按产品章节定义；当前仅送餐车 |
| A-BOX -> 平台 | 主动状态、故障及安全停止上报 | `/zxwl/abox/{deviceId}/status/report` | 按产品章节定义；当前仅顶飞翼 |
| A-BOX -> 平台 | 心跳 | `/zxwl/abox/{deviceId}/heartbeat` | 全部产品 |

设备只订阅自身精确的请求 Topic，不使用会接收到自身响应或上报消息的宽泛通配订阅。

当前 Topic 分工如下：送餐车的 `check_locker_status` 使用 `/status` 和 `/status/resp` 按需查询；顶飞翼不定义平台状态查询命令，通过 `/status/report` 主动上报；所有产品都使用 `/heartbeat` 判断 A-BOX 在线。平台只需实现对应产品声明的 Topic，不应把三种机制同时套用到同一业务。

## 4. 送餐车格口业务

本章只适用于 `product=meal_delivery_vehicle`。

### 4.1 送餐车响应码

| 响应码 | 适用命令 | 送餐车语义 |
|---:|---|---|
| `200` | `open_locker` | 请求中的每个格口均已通过设备反馈确认打开 |
| `200` | `check_locker_status` | 查询流程完成，结果为当前能够确认的格口状态 |
| `400` | `open_locker` | 至少一个格口未能确认打开；`result.gridNos` 返回失败格口 |
| `4001` | 两个命令 | 参数非法、格口号非法，或 `requestId` 冲突 |
| `4002` | 两个命令 | 命令不受当前产品支持 |
| `4003` | 两个命令 | 格口总线、控制流程或查询流程正在占用，暂不能处理 |
| `4004` | 两个命令 | `product` 与设备固化产品不一致 |
| `500` | 两个命令 | 响应超过单包上限，或历史配置中的有效格口数超过 32 个 |
| `5001` | 两个命令 | A-BOX 内部异常 |

格口状态遵循“未证实即不宣称”的原则：

1. 对于配置为双锁的格口，只有两个锁控端点均反馈打开，才可返回该格口打开成功。
2. `open_locker` 完成后，只有最终 `gridStatus=open` 的格口视为成功；`closed`、`partial` 或 `unknown` 均返回 `400`，并把对应格口列入 `result.gridNos`。
3. `check_locker_status` 查询流程正常完成时返回 `200`，各格口的真实结果通过 `gridStatus` 四状态表达；存在 `partial` 或 `unknown` 不改变本次查询响应码。
4. `200` 不是“指令已入队”；它必须满足本节定义的设备反馈边界。
5. 单台送餐车最多配置 32 个有效格口；指定格口请求一次最多携带 32 个不重复编号。`["all"]` 表示当前已配置的全部格口，数量同样不得超过 32 个。

`gridStatus` 枚举：

| 值 | 判定条件 |
|---|---|
| `open` | 两个锁控端点均取得有效反馈，且均为打开 |
| `closed` | 两个锁控端点均取得有效反馈，且均为关闭 |
| `partial` | 两个端点反馈均有效，但一个打开、一个关闭 |
| `unknown` | 任一端点故障、超时、未配置，或无法取得有效状态 |

判定优先级为：`unknown` > `partial` > `open`/`closed`。平台不得把 `partial` 或 `unknown` 展示为已关闭。

### 4.2 打开格口

请求 Topic：`/zxwl/abox/{deviceId}/ctrl`
响应 Topic：`/zxwl/abox/{deviceId}/ctrl/resp`

#### 4.2.1 打开指定格口

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "meal_delivery_vehicle",
    "requestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "command": "open_locker",
    "params": {
      "gridNos": ["1", "2", "6"]
    }
  }
}
```

#### 4.2.2 打开所有格口

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "meal_delivery_vehicle",
    "requestId": "8e1025d1-754c-4b35-a50f-c7275fde5f9b",
    "command": "open_locker",
    "params": {
      "gridNos": ["all"]
    }
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `command` | String | 是 | 固定为 `open_locker` |
| `params.gridNos` | Array&lt;String&gt; | 是 | 1～32 个不重复格口编号，或仅包含 `"all"` 的数组 |

`"all"` 不得与具体格口编号同时出现。

#### 4.2.3 格口控制响应

成功：

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "meal_delivery_vehicle",
    "requestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "code": 200,
    "msg": "操作成功",
    "result": null
  }
}
```

失败：

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "meal_delivery_vehicle",
    "requestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "code": 400,
    "msg": "格口打开失败",
    "result": {
      "gridNos": ["1"]
    }
  }
}
```

失败响应中的 `result.gridNos` 为打开失败的格口编号列表。

## 5. 顶飞翼业务

本章只适用于 `product=top_flying_wing`。

### 5.1 状态语义边界

飞翼控制器可向 A-BOX 提供：

- 命令允许或拒绝；
- 多根推杆的平均位置，单位为 mm；
- `moving` 或 `stopped` 运行状态；
- E01-E16 故障码。

当前硬件不能直接提供上升或下降方向、电流、电压、温度、单根推杆位置或机械动作完成原因，因此这些内容不得作为平台可依赖的状态字段。

`ascending` 和 `descending` 由 A-BOX 根据最近一次已接受且未取消的远程动作推断，不是控制器直接反馈。方向无法可靠确定时必须使用 `moving_unknown`。

### 5.2 三个独立控制动作

应用层只提供三个独立动作：

| 动作 | 含义 |
|---|---|
| `ascend` | 请求上升，不隐含停止操作 |
| `descend` | 请求下降，不隐含停止操作 |
| `stop` | 明确取消当前锁存动作 |

控制规则：

1. `ascend` 和 `descend` 不得在开始动作前隐式发送 `stop`；改变方向仍必须由平台先明确停止并等待停止确认。A-BOX 读取到控制器限位后，可在已接受的远程动作到达目标端点时自动发送一次 `stop` 收尾。
2. 完整空闲时 A-BOX 不发送 `RD`、`RL` 或 `ST`，状态使用 `canSession=idle_silent`、`statusFresh=false`、`controllerOnline=null` 和 `motionState=unknown` 表示；位置及限位可保留上一次远程会话结果。
3. 收到新的 `ascend` 或 `descend` 后，A-BOX 依次执行 `RD`、静默 250 ms、第二次 `RD`、`RL`。任一次 `RD` 发现运动均返回 `4003`，提示现场触摸正在操作，且不得发送 `ST`、`UP` 或 `DN`；任一次查询 300 ms 无回复或限位非法均拒绝远程动作。
4. 两次 `RD` 均确认停止且 `RL` 返回合法限位后，设备只发送一次 `UP` 或 `DN`；命令确认后进入远程会话。
5. 远程运行期间每 100 ms 查询一次 `RD`。到目标端点 2 mm 范围、反馈超时、故障、最长运行 120 秒、位置连续两次反向且累计超过 3 mm，或未到端点却意外停止时，只发送一次 `ST` 收口。
6. `stop` 可抢占预检、启动或远程运行；被抢占的方向请求取消，停止命令仍只发送一次。空闲静默时的 `stop` 按幂等成功处理，不发送 CAN `ST`。
7. `stop` 只有在飞翼控制器接受停止命令且状态确认 `stopped` 后才返回 `200`，随后才能将 `activeAction` 清为 `null`。
8. `stop` 未取得停止确认时不得清除 `activeAction` 或宣称机械已停止：控制器离线返回 `5002`，等待应答或状态确认超时返回 `5003`，明确拒绝返回 `5004`，故障导致无法停止返回 `5005`。
9. 已经处于 `stopped`、`activeAction=null` 且无故障时，`stop` 按幂等成功处理。
10. MQTT QoS 1 导致相同 `requestId`、相同内容重复投递时，不视为新的控制请求；设备按第 2.6 节返回首次响应，不重复执行。
11. 只有本机存在待处理的 `RD` 或 `RL` 时才接受对应回复；空闲时其他节点发送的查询或控制器回复不得污染状态或启动后续查询。
12. 远程会话结束后立即恢复 `idle_silent`，不保留任何本地运动探测查询。协议没有控制来源或方向字段，同方向现场触摸无法与远程命令可靠区分，此限制必须在平台明确展示。

控制准入矩阵：

| 当前条件 | 新 `ascend` / `descend` | `stop` |
|---|---|---|
| `canSession=idle_silent` 且 A-BOX 在线 | 进入完整预检 | 幂等成功，不发送 `ST` |
| 预检发现控制器不可达 | 拒绝，`5002` | 不适用 |
| 预检发现现场运动 | 拒绝，`4003`，不干预现场动作 | 允许抢占预检并尝试停止 |
| 预检发现故障 | 拒绝，`5005` | 作为安全动作尝试，按实际停止结果返回 |
| `canSession=preflight/remote_running` | 拒绝，`4003` | 允许抢占 |
| `canSession=stopping` | 拒绝，`4003` | 合并已有停止，不重复下发 |

### 5.3 飞翼状态模型

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `action` | String | 控制响应是 | 本次请求动作：`ascend`、`descend`、`stop` |
| `accepted` | Boolean | 控制响应是 | 本次动作是否被接受 |
| `motionState` | String | 是 | 当前运动状态 |
| `activeAction` | String / null | 是 | 当前已接受且未取消的锁存动作；没有时为 `null` |
| `positionMm` | Integer / null | 是 | 飞翼控制器返回的多推杆平均位置；从未取得时为 `null` |
| `topLimitMm` | Integer / null | 是 | 飞翼控制器返回的最高限位；尚未取得有效限位时为 `null` |
| `bottomLimitMm` | Integer / null | 是 | 飞翼控制器返回的最低限位；尚未取得有效限位时为 `null` |
| `atEndpoint` | String / null | 是 | 当前位于 `top` 或 `bottom` 端点；不在端点或限位未知时为 `null` |
| `faultCode` | String / null | 是 | `E01`-`E16`；无故障时为 `null` |
| `controllerOnline` | Boolean / null | 是 | 活动远程会话中控制器是否在线；空闲静默时为 `null` |
| `statusFresh` | Boolean | 是 | 状态是否来自当前活动远程会话；为 `false` 时位置和限位属于上次会话数据 |
| `canSession` | String | 是 | `idle_silent`、`preflight`、`remote_running`、`stopping` 或 `fault` |
| `controlOwner` | String | 是 | `none`、`remote` 或 `local_suspected` |
| `operationPhase` | String | 是 | `idle`、`checking_motion`、`quiet_guard`、`checking_limits`、`starting`、`running` 或 `stopping` |
| `feedbackAgeMs` | Integer / null | 是 | 最近一次有效控制器状态距当前的毫秒数；从未取得状态时为 `null` |
| `lastRequestId` | String / null | 是 | 最近一次被接受的远程控制请求；没有时为 `null` |
| `runElapsedMs` | Integer | 是 | 本轮实际连续运动时间；未运动时为 `0` |
| `safetyStopReason` | String / null | 是 | A-BOX 安全停止原因；未触发时为 `null` |

`motionState` 枚举：

| 值 | 说明 |
|---|---|
| `unknown` | 尚无足够信息判断状态 |
| `stopped` | 飞翼控制器反馈停止 |
| `ascending` | 正在运动，A-BOX 根据 `activeAction=ascend` 推断方向 |
| `descending` | 正在运动，A-BOX 根据 `activeAction=descend` 推断方向 |
| `moving_unknown` | 飞翼控制器反馈运动，但方向无法可靠确定 |
| `fault` | 飞翼控制器在线且存在 E01-E16 故障 |
| `offline` | 飞翼控制器离线或无法取得有效状态 |

状态判定优先级为：`offline` > `fault` > `stopped`/运动状态。

`safetyStopReason` 枚举为：`feedback_timeout`、`max_runtime`、`controller_fault`。未触发安全停止时为 `null`。

### 5.4 顶飞翼响应码

本节中的 `5002`～`5005` 为 `product=top_flying_wing` 独占响应码，只能用于顶飞翼控制语义，不得用于送餐车。

| 响应码 | 适用命令 | 顶飞翼语义 |
|---:|---|---|
| `200` | `wing_control` | 控制器接受本次动作，且 A-BOX 已取得满足本次处理要求的新鲜有效反馈；不表示机械动作完成 |
| `4001` | `wing_control` | 参数非法、动作非法，或 `requestId` 冲突 |
| `4002` | `wing_control` | 命令不受当前产品支持 |
| `4003` | `wing_control` | 飞翼正在运动、方向未知运动、存在未取消的锁存动作，或控制流程繁忙；除 `stop` 外的新动作被拒绝 |
| `4004` | `wing_control` | `product` 与设备固化产品不一致 |
| `5001` | `wing_control` | A-BOX 内部异常 |
| `5002` | `wing_control` | 发送控制命令前已判定飞翼控制器离线，无法确认指令下发 |
| `5003` | `wing_control` | 当前状态不足以安全接受运动动作，或等待控制器应答、状态确认超时 |
| `5004` | `wing_control` | 飞翼控制器明确拒绝执行 |
| `5005` | `wing_control` | 飞翼控制器存在 E01-E16 故障，无法接受运动动作或完成安全停止 |

`5002` 与 `5003` 的区别：前者表示命令发送前已有离线结论，后者表示处理本次命令时等待应答或新鲜反馈超时。

### 5.6 飞翼主动状态、故障与安全停止上报

Topic：`/zxwl/abox/{deviceId}/status/report`
方向：A-BOX -> 平台
QoS：1
Retain：是

```json
{
  "version": "2.0",
  "timestamp": 1770186088333,
  "data": {
    "product": "top_flying_wing",
    "reportId": "V000001-1770186088333-1024",
    "reportReason": "periodic",
    "motionState": "ascending",
    "activeAction": "ascend",
    "positionMm": 126,
    "faultCode": null,
    "controllerOnline": true,
    "feedbackAgeMs": 32,
    "lastRequestId": "3fa85f64-5717-4562-b3fc-2c96063f8666",
    "runElapsedMs": 4820,
    "safetyStopReason": null
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `reportId` | String | 每个逻辑状态报告的唯一标识；QoS 重发必须保持不变 |
| `reportReason` | String | 本次上报原因，枚举见下表 |

| `reportReason` | 触发条件 |
|---|---|
| `periodic` | 周期状态上报 |
| `state_changed` | 运动状态或锁存动作发生变化 |
| `controller_offline` | 飞翼控制器离线或状态超时 |
| `controller_online` | 飞翼控制器恢复在线 |
| `fault_raised` | 故障产生或故障码变化；具体故障见 `faultCode` |
| `fault_cleared` | 故障解除，`faultCode=null` |
| `safety_stop` | A-BOX 触发安全停止；具体原因见 `safetyStopReason` |
| `endpoint_stop` | 已接受的远程动作到达目标端点，A-BOX 单次发送停止命令或完成停止确认 |
| `control_conflict` | 位置反向或未到端点意外停止，怀疑现场触摸介入并单次发送停止命令 |

上报时机：

- A-BOX 建立 MQTT 连接后上报 `idle_silent`，不为取得初始控制器状态而发送 CAN 查询；
- 预检、读取限位、启动、运行和停止阶段发生变化时立即上报，远程运行中的位置更新随 100 ms 查询结果实时上报；
- 开始、停止、故障产生或解除、安全停止及控制冲突时立即上报，并填写对应的 `reportReason`；
- 停止且无状态变化时不重复上报，由 Broker 保存的最新状态供平台订阅时读取；
- 平台按 `reportId` 幂等处理，并按 `timestamp` 丢弃过期状态。

Retain 消息只代表最近一次业务状态，不证明 A-BOX 当前在线。平台必须使用心跳判断 A-BOX 在线状态；A-BOX 离线时，可以展示最后状态，但必须同时标记为离线或历史状态。

控制请求已经返回 `200` 后发生的异步故障、控制器离线或运行超时，不得追溯修改原响应；设备必须通过本 Topic 上报最新状态。

### 5.7 设备侧安全行为

本节只定义平台能够观察到的安全结果。A-BOX 与飞翼控制器之间使用何种总线、帧格式、查询周期、重试次数和内部超时时间，属于设备内部实现，不作为平台对接协议的一部分。

1. A-BOX 必须保证单个业务请求不会导致底层控制指令被重复执行。
2. 运动期间反馈超时，A-BOX 尽力发送停止，设置 `safetyStopReason=feedback_timeout`，并以 `reportReason=safety_stop` 立即上报状态。
3. 连续运动达到运行上限，A-BOX 发送停止；停止确认成功后以 `reportReason=safety_stop`、`safetyStopReason=max_runtime` 上报状态。
4. 运动期间出现 E01-E16，A-BOX 尽力发送停止，并分别上报故障状态和安全停止状态。
5. MQTT 断开本身不取消已经接受的运动动作，但控制器状态监测和运行上限计时必须继续工作。
6. 如果安全停止无法获得停止确认，平台不得把机械停止视为已证明；设备应上报真实的控制器在线状态和最后反馈年龄。
7. 反馈超时阈值和连续运行上限由设备配置管理；如需平台配置，应由独立的设备配置协议定义，不在本业务协议中固定数值。

## 7. 顶飞翼 E01-E16 故障码

本章只适用于 `product=top_flying_wing`。平台应保存原始 `faultCode`，展示文案可按下表映射，不得只保留统一的 `5005`。

| 故障码 | 含义 | 处理说明 |
|---|---|---|
| `E01` | 遇阻回退 | 推杆运动遇阻后回退，错误可能自动消除 |
| `E02` | 同步偏差告警 | 多通道霍尔位置偏差超过控制器设定值 |
| `E03` | 欠压警告 | 检查输入电源和负载 |
| `E04` | 倾斜警告 | 多推杆同步异常导致倾斜超过阈值 |
| `E05` | 通道 1 过流 | 检查通道 1 负载和堵转 |
| `E06` | 通道 2 过流 | 检查通道 2 负载和堵转 |
| `E07` | 通道 3 过流 | 检查通道 3 负载和堵转 |
| `E08` | 通道 4 过流 | 检查通道 4 负载和堵转 |
| `E09` | 电源过流 | 检查总负载和电源容量 |
| `E10` | 通道 1 霍尔无信号 | 检查推杆、连接和堵转 |
| `E11` | 通道 2 霍尔无信号 | 检查推杆、连接和堵转 |
| `E12` | 通道 3 霍尔无信号 | 检查推杆、连接和堵转 |
| `E13` | 通道 4 霍尔无信号 | 检查推杆、连接和堵转 |
| `E14` | 过热警告 | 停止运行并等待控制器降温，错误可能自动消除 |
| `E15` | 密码或注册错误 | 控制器未注册或注册信息异常 |
| `E16` | 异常断电报警 | 推杆运动期间断电，需要按控制器要求复位消除 |
