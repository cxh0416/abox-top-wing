# 飞翼控制实现与安全验收

本文档面向固件开发、硬件联调和现场验收，不属于公共平台协议。平台对接只需阅读 `docs/protocols/A-BOX飞翼设备业务协议-V4.0.md`。

当前源码构建标识：`top-flying-wing-1.1.0`

## 1. 硬件反馈边界

控制器可返回命令接受/拒绝、多推杆平均位置、运动/停止状态和 E01～E16 故障码，不能直接返回运动方向、电流、电压、温度、单根推杆位置或机械动作完成原因。

固件根据已接受且未取消的远程动作推断 `ascending` 或 `descending`；无法可靠确定方向时使用 `moving_unknown`。完全空闲时不主动轮询控制器，诊断扩展字段可表现为 `canSession=idle_silent`、`statusFresh=false`、`controllerOnline=null`。

## 2. 控制流程

1. 新的升降请求先执行两次运动检查，两次之间静默 250 ms，再读取限位。
2. 发现现场运动、查询超时、故障或限位非法时拒绝远程升降。
3. 预检通过后只发送一次 `UP` 或 `DN`，远程运行期间周期读取状态。
4. `stop` 可以抢占预检、启动和远程运行；空闲时的显式停止也调用同一停止确认流程。
5. `stop` 只有取得控制器接受和 `stopped` 反馈后才返回成功并清除动作锁存。
6. 到达目标端点、反馈超时、控制器故障、连续运行达到上限、位置反向或未到端点意外停止时，只触发一次停止流程收口。
7. 相同 `requestId`、相同请求内容的重复投递只返回首次响应，不重复下发控制。

## 3. 安全行为

- 反馈超时：尽力停止，并报告 `safetyStopReason=feedback_timeout`。
- 达到最长连续运行时间：停止确认后报告 `safetyStopReason=max_runtime`。
- 控制器故障：尽力停止，并保留原始故障码。
- MQTT 断开：不取消已经接受的动作，控制器监测和运行上限计时继续。
- 未取得停止确认：不得宣称机械已经停止。
- 方向切换：必须经过独立的停止请求和停止确认，不在升降命令中隐式换向。

反馈超时和最长运行时间属于设备配置，不通过公共业务协议修改。

## 4. 诊断扩展字段

当前固件状态报文还可能包含以下诊断字段，供设备维护和问题定位使用，平台基本业务不得依赖：

| 字段 | 当前含义 |
|---|---|
| `canSession` | `idle_silent`、`preflight`、`remote_running`、`stopping` 或 `fault` |
| `controlOwner` | `none`、`remote` 或 `local_suspected` |
| `operationPhase` | 当前内部控制阶段 |
| `feedbackAgeMs` | 最近有效控制器反馈年龄 |
| `runElapsedMs` | 本轮连续运动计时 |

## 5. 控制器故障码

| 故障码 | 含义 |
|---|---|
| `E01` | 遇阻回退 |
| `E02` | 同步偏差告警 |
| `E03` | 欠压警告 |
| `E04` | 倾斜警告 |
| `E05`～`E08` | 对应通道过流 |
| `E09` | 电源过流 |
| `E10`～`E13` | 对应通道霍尔无信号 |
| `E14` | 过热警告 |
| `E15` | 密码或注册错误 |
| `E16` | 异常断电报警 |

具体诊断和处置以厂家控制器资料及现场检测结果为准。

## 6. 验收边界

- 构建、单元测试和 MQTT 响应只能证明软件及接口行为。
- OTA 接受响应不能单独证明安装成功，应核对实际运行版本和 Boot 确认状态。
- MQTT 状态不能单独证明真实机械运动，升降、端点和现场控制冲突必须在安全条件下进行硬件验收。

## 7. V4 通信适配边界

- 公共协议、SHA-256/JCS、Topic、有效期、EC800 MQTT/TLS、Cloud 启动顺序和时钟直接链接平台组件；产品侧只维护 `wing 1.0`、控制器适配、请求记录和报文内容。公共 Boot 二进制继续使用原冻结产物。
- 顶飞翼不新增 `0x0803E000` 配置恢复页；发布复用本仓库的冻结契约校验，保持 App 末端为 `0x0803E7FF`，不能套用其他产品的恢复页默认布局。
- 升降预检、250 ms 静默、100 ms 反馈轮询、端点/冲突/故障/超时安全停止及单次停止收口保持原流程。控制器新增的观察接口只保存生成时快照和请求关联；只有“空闲显式停止”补齐原有停止确认流程，不再直接成功。
- 控制请求 ID 容量为 64 个 ASCII 字符。报告保存确认时的不可变快照，避免进入空闲静默后把已取得的停止反馈丢掉；快照和结果的复制使用短临界区。
- 升降请求在执行前写入配置页尾部的持久记录，键为设备 ID 和请求 ID，摘要使用公共规范。配置主体仍位于原地址，日志从页内偏移 512 开始，9 个 168 字节槽，不改变 Boot State A/B 或配置页边界。先提交预留、再执行、再保存首次响应；重启后结果不确定的记录拒绝再次执行。保护期内不覆盖记录，槽满返回忙；受保护记录存在时配置保存返回忙。损坏记录阻止新升降，但停止和状态同步仍可使用。
- 公共 TLS 使用模组实际探测到的上下文 2，HTTPS OTA 继续保留上下文 1；复用已核验的 `UFS:ota_ca.pem`，启用证书验证、SNI 和时间检查。配置试用只在匹配响应确认后开始，只有新连接心跳确认后才保存，失败恢复原配置。
- 内部授时复用公共三样本、RTT/误差约束和时钟质量模型。CCLK 只作启动时间；业务有效期使用可信时钟并在持久预留后再次检查。单调时钟复用平台 TIM2 实现，保持原控制超时与周期数值，避免 Flash 操作阻断普通 HAL tick 时丢失经过时间。

主机回归覆盖原控制与安全流程、空闲停止及端点换向、V4 重投/冲突/过期、重启与写入中断、报告 QoS/关联、TLS 授时和配置回退。它们不替代真实模组、Broker、机械及 OTA 验收。
